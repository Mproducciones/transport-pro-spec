--- ARRANQUE RÁPIDO (cuando enciendas la PC) ---
1) PostgreSQL / Docker (lo que uses) → que esté corriendo.
2) backend/.env → DATABASE_URL apuntando a tu base REAL (no placeholder tipo example.com).
3) Terminal backend:
   cd backend
   npm run dev
4) Terminal frontend:
   cd frontend
   npm run dev
5) Limpiar solo viajes/facturas/pagos y mantener cuentas demo (slugs demo, andescargo, patagoniaruta):
   cd backend
   npm run wipe:demo-operational
6) Datos demo multi-rol (después del wipe o en BD vacía):
   cd backend
   npm run seed:test-agents
7) Simulación admin pasado/hoy/futuro (Chile): npm run seed:admin-simulation
   Guía: docs/SIMULACION_EQUIPO_ADMIN.md
8) Cuentas: ver docs/AGENT_TEAM.md (empresa.agente@demo.com, cliente.agente1@demo.com, etc.)

--- PRUEBAS ÚTILES (API levantada) ---
  cd backend
  npm run test:unit
  npm run verify:auth-roles
  npm run smoke:critical        (opcional, flujo crítico)
  npm run smoke:billing         (opcional, facturación/pagos)

--- QUÉ QUEDÓ CONFIGURADO (no hace falta volver a pedirlo) ---
• .cursor/rules/transport-pro-agent-team.mdc  → regla siempre activa: ciclo Manager,
  full stack, personas; si pedís "pruebas" usa seed:test-agents + scripts + cuentas del doc.
• AGENTS.md → puntero a esa regla y al equipo virtual.
• docs/AGENT_TEAM.md → roles, ciclo, credenciales demo, flujos críticos.

--- CAMBIOS IMPORTANTES EN PORTAL CLIENTE (UX) ---
• Vista "Resumen" (antes Inicio): primero "Lo primero que necesitás ver", luego pedido
  destacado y pagos, luego números, desglose, solicitar envío, índice "¿Buscás otra cosa?".
• Móvil "Más": en sección Pedidos no repite En curso/Mapa/Historial (ya están en pestañas).
• Mini checklist de comprobantes en Resumen: mismos datos que ClienteLayout (query
  cliente-payments-alert), enlace directo a /cliente/pagos si hay rechazados o pendientes.
• Reducción de redundancias en facturas/pagos/envíos (menos botones duplicados; un solo
  "Ver comprobante" en lista de pagos, etc.).

--- SI ALGO FALLA ---
• seed:test-agents → revisar DATABASE_URL y que Postgres acepte conexiones.
• verify:auth-roles → backend debe estar en el puerto esperado (ej. 4000).

--- PRÓXIMOS PASOS OPCIONALES ---
• Más pulido de copy o métricas en cliente.
• E2E automatizado (hoy no hay suite en frontend).
